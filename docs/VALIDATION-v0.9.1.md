# XGuard 0.9.1 验证记录

验证日期：2026-11-17。此版本为本地交付构建，未创建 GitHub Release。

## 实现与边界

- GKD 独立底栏页面，六个底栏位置；底栏透镜切换为 0.55 秒，表面略透明，保留减少动态效果的系统设置。
- 首次打开显示 Root / VPN 与无障碍授权向导；返回后实查无障碍状态。逐来源独立勾选、更新，可填写 HTTPS URL 下载、缓存并删除自定义订阅；所有来源都关闭时不执行规则。
- 仅实现 GKD 开屏规则兼容子集，未引入完整 GKD 应用或完整选择器引擎。复杂关系、正则、版本过滤、前置动作等不支持条件整条拒绝。实际 Lin-arm 订阅版本 636：82 条可执行，3873 条未导入。数量随上游更新变化。
- Root 模块增加无障碍守护，默认关闭；须首次手动开启过服务。复用原有 watchdog，每 120 秒检查，恢复至少间隔 300 秒，不加唤醒锁。只恢复 XGuard，保留其他服务；安全模式、模块禁用/待卸载、切换用户及首次解锁前暂停。手动关闭无障碍前应先关闭守护。免 Root 版明确提示无法自动恢复系统授权。
- GPLv3 全文、GKD 参考与改编范围、社区来源归属、源码构建说明已随交付提供。

## 实机结果

在已连接的 KernelSU/SukiSU 手机安装模块包成功，最终 APK 和守护脚本已同步加载到当前运行模块，无需再次重启；下一次重启使用同一暂存模块。未清除任何正式应用数据。

无障碍守护已在手机开启。测试移除 XGuard 授权后，手动调用检查与真实后台定时检查均能恢复 XGuard 并重新绑定；原有 SCENE 服务仍保留。后台日志记录恢复请求，ActivityManager 显示 `hasBound=true`。模块状态 `daemon=running`、`health=ok`，154540 条域名规则、5 个域名来源、8 个缓存锁定应用。

三款应用冷启动观察：学习通出现过短暂广告，后续产生 `com.chaoxing.mobile · xguard-local` 新执行记录并进入登录页；移动云盘与迅雷进入主界面，本轮未观察到持续广告，不能仅凭主界面认定 GKD 命中或全部开屏都已消除。未做多天耗电对比，不能给出节电百分比。

原始设备截图、测试备份仅在本地 `dist/device-check`，未纳入源码 ZIP。用户排除的整机网络故障未纳入此次处理范围。
